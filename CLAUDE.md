# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal recipe site ("Recetario") built with Jekyll 4 and served at https://recetario.marrese.com.ar (see
`CNAME`). All content and UI text is in Spanish (`lang: es`). There is no README, test suite or linter.

## Commands

Local builds use the Homebrew Ruby 4.0 and its bundled Bundler (no Ruby version manager); gems live in the project,
not system-wide.

```sh
bundle config set --local path vendor/bundle   # once per clone: install gems into vendor/bundle (gitignored)
bundle install                 # install gems from Gemfile.lock
bundle exec jekyll serve       # local preview at http://localhost:4000 (restart after editing _config.yml)
bundle exec jekyll build       # build into _site/
```

Deployment is automatic: pushing to `main` runs `.github/workflows/jekyll-gh-pages.yml`, which builds with Ruby 4.0
and `JEKYLL_ENV=production` and deploys to GitHub Pages. A push to `main` publishes the live site. Keep the
workflow's `ruby-version` in step with the local Ruby.

`Gemfile.lock` is locked to Bundler 4.0.20. A plain `bundle update --bundler` locks the newest release, prereleases
included, so pass the version: `bundle update --bundler=4.0.20`.

## Architecture

- **Recipes** are plain Markdown pages in `recipes/` (not a Jekyll collection). Each has front matter:
  `layout: libdoc/page-recipe`, `title`, `category: recetas`, `tags` (YAML list), `tiempo_preparacion`,
  `tiempo_coccion`. The body has a `## Ingredientes` section (a bullet list) followed by `## Preparación`.
- **Homepage** (`index.html`) builds the recipe grid by selecting `site.pages` whose layout is
  `libdoc/page-recipe`, so a new recipe only appears there if it uses that layout. Tag filter buttons are collected
  from all recipes' `tags` at build time; search and tag filtering are client-side JS over `data-title` / `data-tags`
  attributes (lowercased, accents ignored). A card's colour comes from the first tag in `index.html`'s `cat_order`
  list that the recipe has (`data-cat`, mapped to `--cat-*` colours in the CSS).
- **Recipe layout** (`_layouts/libdoc/page-recipe.html`) post-processes the rendered Markdown in the browser: it
  finds the headings by their kramdown auto-generated ids (`ingredientes`, `preparación`/`preparacion`), turns every
  list between them into checkboxes, and puts each section in its own column. Steps (list items and paragraphs
  after "Preparación", up to the next `#`/`##` heading such as "Notas") can be tapped to mark them done, and a
  paragraph that is only a bold label (`**El armado**:`) is styled as a sub-heading. Ticked ingredients and done
  steps are remembered per recipe in `localStorage`. Renaming those two headings breaks this.
- Layout chain: `libdoc/page-recipe` and `libdoc/page` both extend `_layouts/default.html` (header, footer,
  `{% seo %}`, Google Fonts). All styling is in `assets/css/style.css`; icons are inline SVGs in
  `_includes/icon.html`.
- **Offline:** `sw.js` (a service worker, generated by Liquid) saves the homepage, CSS and every recipe page when
  first visited, serves pages from the network when possible and from that copy otherwise. `manifest.webmanifest`
  and `assets/icons/` let it be added to a phone's home screen.
- `recipes/template.md` is gitignored, so it may exist locally as a personal starting point but isn't in the repo.
